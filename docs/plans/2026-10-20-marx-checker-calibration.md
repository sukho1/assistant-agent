# 检查器校准、无条件平等与人民归属优化

日期：2026-10-20。用户同意 PRD 后提出的五项建议，范围原 AA 与小庄 Web，双平台技能同步。使用既有授权的内部提示词和原六个合成问题；不访问真实档案或生产数据库，不部署。

## 目标和边界

上轮短探针通过而长回答仍失败：检查器漏掉个人因果与等级命题，误伤劳动肯定，并在反馈中发明新的心理解释。先用冻结的完整失败段校准检查与反馈，再补生成端的平等判断和正向归属。保留完整知识、原样例、指导思想与无条件尊重原文。暂不改模型，不先改事实结构或增加线上调用。

## 步骤

- [x] 1. 固定两仓版本、私有技能哈希与现有完整输出，AA 独立工作树；冻结成对的完整问题片段与预期判断。
- [x] 2. 离线校准：同一固定样本分别运行修改前与修改后的 Web 初检、修订复检、AA 技能自检；记录实际提示词、模型参数、检查结果和漏报/误报，不以旧报告代替当前对照。
- [x] 3. 检查反馈明确原句、对应材料、证据缺口或规则；反馈不创造替换经历，返工把反馈当待核验意见而非用户事实。保留现有 pass/issues 契约与一次修订次数。
- [x] 4. 两仓双平台技能及 Web 常驻约束同步整句平等判断：不以某类人的低等反证用户价值，免责声明不能抵消肯定过的错误命题。
- [x] 5. 补小资羞耻等相关场景的正向人民归属：平等共同生活、认同与互助，不把成为正确的人或完成链接任务作为条件，不虚构用户经历。
- [x] 6. 工程验收：针对受影响的组装、反馈隔离、技能路由/全文边界、运行时等做有意义的回归，API 类型和构建；不声称既有基线问题已解决。
- [x] 7. 以校准结果决定是否回原六场景做一次两侧完整复验，保留初稿/检查/修订/交付与人工双向判断。校准无效则停止扩大调用，记录具体阻碍和建议。
- [ ] 8. 更新两仓验收记录和计划，安装私有技能前核对原哈希并备份，提交推送；Web 未关闭整体质量与基线门禁前保留功能分支。

## 对照与停止条件

计划校准使用本轮冻结的八个完整片段（含真实失败和最小修正正例），每例三种检查输入，修改前后各一次；最多48次判定调用，不做统计显著性结论。随后最多一次固定六场景完整复验及必要的技术故障补测。任何严重无据个人事实、认知/疗愈归罪或附条件尊严均为语义失败，候选被拦不能当作合格回答。若检查仍有残余，依据严重程度说明，不反复调参追逐偶然通过。

## 已知边界

AA 仍为实际技能提示词 harness，选文复用 Web；不是原生客户端/日记工具验收。Web 的历史基线门禁另列。此次不把代码引文匹配当成因果证明，也不预先推进材料结构化。

## 校准中发现的范围修正

首组24+24结果为19/24与18/24，未改善，不能据此扩大完整生成。核查实际提示词发现：AA离线自检只加载输出前自检小节，整句平等新规则在上文总原则中，因此没有进入该检查输入。已把操作规则同步放到自检小节使其自包含；同时根据实际误判区分确定的个人信念/功能与一般机制、比喻，明确风格优化不能冒充严重错误。保留首组原报告，增加且仅增加一次修正后的24次校准，不继续追逐偶然通过；这是明确输入缺口与实测误判的修复，尚未宣称有效。

## 本轮验收结果

首组19/24与18/24不改善，纠正自检输入范围及判断边界后24/24判定符合预期，反馈仍有额外误报。已继续原六例一次完整复验：整体质量未通过，Web失业被拦，其他残余和正向归属改善见验收记录；不继续付费重跑，不提前做结构化或换模型。八文件200项回归与路由定点1项、API类型/构建/产物、十二技能校验通过；旧路由SDK分块假设已按交付前复检行为修正。全仓基线、原生AA客户端仍开放，本轮不重复E2E。
